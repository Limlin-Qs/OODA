# 发布、备份与恢复操作边界

本文件对应已接受的 ADR-0008，描述 Phase 1 的可执行操作边界。它不包含真实主机、账号、连接串或凭据。

## 发布顺序

1. 从锁文件执行构建并生成前端 `dist/` 与服务端 `server-dist/`。
2. 由发布环境注入 `DATABASE_URL`、OIDC 配置和会话相关配置；这些值不进入镜像和前端产物。
3. 在兼容窗口执行 `npm run migrate`。迁移使用版本表和 PostgreSQL advisory lock，重复执行不会重复应用。
4. 发布 `ops/Dockerfile` 构建的服务容器，由 HTTPS 反向代理对外提供访问。
5. 检查 `/healthz`，再开放流量；服务端日志不得输出连接串、会话令牌或联系人明文。

## 备份与恢复

- `ops/backup.sh` 使用 PostgreSQL custom dump，并立即执行 `pg_restore --list` 基本完整性检查。
- `ops/restore.sh` 只有在目标库和备份已人工核对后，显式设置 `CONFIRM_RESTORE=YES` 才会执行覆盖恢复。
- `ops/recovery-rehearsal.sh` 将源库备份恢复到隔离目标库，并查询迁移表，作为恢复演练入口。
- 备份文件应保存到独立于数据库主机的位置；具体保留周期、责任人和存储提供商需由部署负责人补充。

## 回退

应用发布失败时回退到上一份已验证的镜像，保留已提交的领域事实。数据库只允许执行向前兼容迁移；不可逆结构变更先完成恢复演练，不通过回退应用来改写审计历史。

## 验收记录

发布前必须记录以下证据：构建版本、迁移输出、健康检查结果、备份文件校验、隔离目标库恢复结果和回退演练结果。真实生产凭据、个人联系方式和会话值不得写入记录。
