# PRD — 创新工作室物资共享系统

> 状态：v0.3，业务与技术边界已于 2026-09-14 确认。本文描述产品目标和约束，不代表功能已经实现。仓库当前仍是 Vite React 模板。

## 1. 产品定位

面向一个创新工作室的物资共享与设备借用系统，心智模型类似图书馆借阅：把每件设备作为可追溯的独立资产，成员可查询、借用、归还和预约，管理员维护台账与异常状态，系统保留责任人与状态历史并计划提供超期提醒。

设备是带资产编号、序列号、附件和维护历史的非标固定资产，不能直接套用“书目—副本—借阅卡”模型。

## 2. 已确认的目标与规模

- 用户：单个创新工作室的成员和管理员。
- 规划规模：设备 50–300 件、用户 20–100 人。这是产品规划范围，不是已有运行数据、容量测试结果或 SLA。
- 客户端：首版为 Web。
- 核心价值：清楚回答“有什么、现在谁在用、何时归还、未来谁预约过、状态为何变化”。
- 正确性优先级：多人操作下不能出现双重占用、无责任人借用或无法追溯的状态变化。

## 3. 首版范围

计划包含：

1. **设备台账**：登记、编辑、查询设备及其分类、状态、归属、附件清单、图片和维护信息。
2. **借还流转**：借出、归还，记录借用人、借出时间、应还时间、实际归还时间、交接备注和损坏信息。
3. **预约**：按未来时间区间预约单台设备，并拒绝冲突区间。
4. **超期提醒**：到达应还时间仍未归还时生成一次可追踪、可重试且去重的站内提醒。
5. **状态审计**：记录关键业务状态变化的操作者、时间、原因及前后状态。

明确不含：

- 贵重或危险设备的资质准入、培训记录和计时使用。
- 耗材库存管理。
- 折旧、计费、押金和赔偿结算。
- 多工作室或多租户。
- 原生移动端或小程序。

报废字段曾出现在早期草案中，但“报废/折旧流程”又被列为首版排除项。本版首版支持维修、丢失、停用/归档等不可借用状态，不实现完整报废审批、折旧或财务流程。附件首版只保存附件说明和维护备注，不上传二进制文件。

## 4. 核心场景

- S1：管理员登记或维护一台设备，系统确保资产标识不冲突。
- S2：成员查看设备信息及可信的当前/未来可用性。
- S3：有权限的成员发起借用；系统在并发情况下也只允许一个有效占用者。
- S4：借用人本人或管理员直接完成归还；损坏信息作为归还备注记录，必要时管理员将设备转入维修状态。
- S5：成员预约未来区间；系统拒绝与有效借用或预约重叠的请求。
- S6：借用超过应还时间后，系统记录并尝试发送不重复的提醒。
- S7：管理员查询关键状态变化和责任链，但不能通过正常功能改写历史。

## 5. 业务红线与验收不变量

- **资产身份稳定**：每台设备有稳定的系统 ID 和服务端生成的唯一资产编号。序列号非必填，填写时全系统唯一。
- **占用互斥**：同一设备的有效借用与有效预约不得在同一时间重叠；该规则必须在并发请求下仍成立。
- **责任明确**：每个有效借用和预约必须关联有效成员；所有状态变化必须记录经验证的操作者。
- **状态合法**：设备、借用和预约只能按已确认状态机流转；取消、归还和异常处理不得靠覆盖旧记录完成。
- **审计只追加**：成功的关键状态变化产生只追加审计；业务写入和审计必须同成同败。审计保留与个人信息匿名化按后续隐私规则处理，不通过普通功能改写历史。
- **引用完整**：被借用、预约或审计引用的设备和成员不能因普通删除操作而造成悬空记录。
- **服务端权威**：成员身份、服务端时间和持久化记录是占用与超期判断的依据；浏览器状态不作为权威事实。业务时区为 `Asia/Shanghai`，预约精确到分钟。

第一阶段验收至少证明：并发双借被拒绝、重叠预约被拒绝、越权操作被拒绝、重复请求不产生重复副作用、状态变化可追溯。

## 6. 概念模型（非数据库设计）

下列实体用于澄清业务语言，字段、表结构和存储技术尚未决定：

- **Device（设备）**：系统 ID、资产编号、名称、序列号、分类、业务状态、归属、附件/图片引用、维护信息。
- **Member（成员）**：系统 ID、显示名称、必要联系方式、角色、账号/成员状态。
- **BorrowRecord（借用记录）**：设备、借用人、借出时间、应还时间、实际归还时间、生命周期状态、交接/损坏信息。
- **Reservation（预约）**：设备、预约人、起止时间、生命周期状态、取消/完成信息。
- **AuditEntry（审计条目）**：对象、动作、操作者、服务端时间、必要的前后状态和原因。
- **NotificationAttempt（概念）**：提醒对象、渠道、幂等标识、尝试时间与结果；是否独立建模待通知方案确认。

“可用”“超期”等值是否存储或实时派生，必须在数据设计时保证只有一个权威来源。

## 7. 角色、权限和可见性

- **管理员**：计划拥有设备台账维护、全局借还/预约处理、异常设备处理、必要统计与审计查看、成员状态管理能力。
- **普通成员**：计划能够查看允许公开的设备信息、仅代表本人发起借用/预约、查看本人记录，并按待确认流程发起或确认归还。
- 普通成员不能修改他人记录、设备台账、角色或审计；设备目录需要登录，普通成员只看到占用状态和时间，不看到他人联系方式。
- 管理员也不能绕过业务状态机或改写审计；代办操作必须记录实际操作者与业务责任人。
- 联系方式仅用于成员识别、借还协作和提醒。公共列表、普通成员视图、日志和导出不得暴露不必要的个人信息。

管理员角色由已确认身份源映射后由服务端管理；成员停用后不能产生新借用或预约，历史记录仍可追溯。

## 8. 一致性、事务与幂等要求

- 借出、归还、预约、取消必须把权限与前置状态检查、领域写入和审计写入纳入同一权威事务边界。
- 冲突校验必须有原子保障；仅在前端或普通应用查询中判断后再写入不能满足要求。
- 可安全重试的写操作必须有明确幂等语义。相同操作重放不得产生第二条有效借用/预约、二次归还或重复审计。
- 同一幂等标识对应不同请求内容时必须拒绝，避免把不同操作误判为重试。
- 提醒任务可能重复调度或重试；重复执行不得对同一提醒阶段反复打扰。
- 外部消息发送失败不应撤销已成立的借还事实；发送意图必须可追踪并支持受控重试。

具体方案见已接受的 [ADR-0003](adr/0003-server-authoritative-transaction-boundary.md)。

## 9. 安全、迁移与交付约束

- 鉴权和授权在服务端执行；前端展示逻辑不能代替权限检查。
- 全链路使用 HTTPS；真实密钥、密码、令牌和连接串不得进入源码、文档、前端构建或日志。
- 身份采用组织现有 OIDC 身份源，服务端使用 HttpOnly 会话；不在本项目实现本地密码登录。
- 数据结构变更通过版本化迁移执行。每次迁移要定义兼容、回填、失败处置和恢复方案，不承诺所有迁移都能直接回滚。
- 审计历史不得由普通迁移删除。个人信息保留与匿名化需要单独确认。
- 部署前必须明确环境隔离、密钥注入、迁移顺序、日志脱敏、备份恢复、发布与回退流程。
- 持久化采用 PostgreSQL 和版本化 SQL 迁移；提醒首版采用站内渠道；部署目标为 Linux 容器化环境并使用 HTTPS 反向代理。业务 API、迁移、站内提醒和前端已在 Phase 1 按任务落地；生产身份源、HTTPS 反向代理和独立备份存储仍需部署负责人配置与人工验收。

## 10. 测试与验收要求

业务实现使用已确认的测试工具与约定。核心规则至少需要：

- 状态机、区间边界、超期与权限的单元测试。
- 事务回滚、并发占用、引用/唯一约束、幂等重放和迁移的集成测试。
- 借出—归还、预约冲突、越权拒绝的端到端测试。
- 提醒重复调度、失败重试和去重测试。

测试基线采用 Vitest、真实 PostgreSQL 集成测试和 Playwright E2E；并发测试不能只使用内存替身。当前已覆盖领域单测、真实 PostgreSQL 集成、并发/事务/幂等/权限/提醒及成员和管理员核心 E2E；不虚构覆盖率数字。

## 11. 已确认决策（2026-09-14）

以下答案由用户确认，作为 Gate 0 实施依据：

1. **借还流程**：成员可直接借出；借用人本人或管理员可直接完成归还；首版不支持续借。
2. **预约语义**：使用半开区间 `[开始, 结束)`，开始早于结束，精确到分钟；预约不自动转为借用；有效借用和逾期借用均阻止重叠预约。
3. **异常设备**：首版支持维修、丢失、停用/归档；不实现完整报废流程。管理员负责异常状态转换，归还时记录损坏备注。
4. **资产标识**：资产编号由服务端生成且全局唯一；序列号非必填，填写时全局唯一；没有序列号的设备可正常登记。
5. **成员生命周期**：身份来自组织现有 OIDC；服务端维护成员映射和角色；停用成员不能新建占用，历史记录保留必要责任链。
6. **可见性**：设备目录需登录；普通成员仅查看状态和占用时段，不查看他人联系方式；管理员按最小权限查看责任链。
7. **提醒**：首版采用站内提醒，仅提醒借用人；应还时间到达后生成一次提醒，写入意图可重试且按借用记录和提醒阶段去重。
8. **时间**：业务时区为 `Asia/Shanghai`；服务端保存带时区时间；预约精确到分钟，区间采用半开语义。
9. **附件与图片**：首版不上传二进制文件，仅保存附件说明、维护备注等文本元数据。
10. **技术与交付**：采用当前活跃 Node.js LTS + TypeScript + Fastify REST/JSON API；PostgreSQL + 版本化 SQL 迁移；OIDC + HttpOnly 会话；Vitest + PostgreSQL 集成测试 + Playwright；Linux 容器化部署、HTTPS 反向代理、独立备份与恢复演练。具体迁移 runner 和部署提供商属于可替换实施细节，在 G-009 中锁定。

## 12. 首版状态机与权限矩阵

### 设备状态

| 当前状态 | 允许下一状态 | 执行角色 |
| --- | --- | --- |
| `available` | `maintenance`、`lost`、`archived` | 管理员 |
| `maintenance` | `available`、`archived` | 管理员 |
| `lost` | `archived` | 管理员 |
| `archived` | 无；终态 | — |

设备状态转换不得通过覆盖历史记录完成；`archived` 设备不能再借用或预约。

### 借用与预约状态

- 借用仅允许 `active → returned`，归还后的记录不可重新打开或覆盖。
- 预约允许 `active → cancelled` 或 `active → completed`，取消和完成均为终态。
- 时间区间为半开区间 `[开始, 结束)`；开始必须早于结束；相邻区间不冲突，实际重叠必须拒绝。
- 借用人本人可借出和归还自己的记录；普通成员不能代他人借用、归还或取消预约。
- 管理员可处理任意成员记录；管理员代成员借用或预约时必须提供原因，并同时记录实际操作者和业务责任人。
- 管理员可执行设备异常状态转换和查看审计；普通成员不能维护设备、变更角色或查看审计。
- 所有命令先确认操作者为有效成员；停用成员拒绝新操作。稳定拒绝语义包括 `forbidden`、`inactive_member`、`invalid_interval`、`invalid_transition` 和 `missing_reason`。

规则实现位于服务端领域模块，并由单元测试、真实 PostgreSQL 集成测试和核心 E2E 覆盖；数据库冲突约束、事务审计、会话身份和服务端授权已实现。

## 13. 当前实现差距

仓库已有 React 设备目录/详情、成员记录工作台和管理员工作台；Fastify REST API；OIDC 验证边界与 HttpOnly 会话；PostgreSQL 版本化迁移；设备、成员、借用、归还、预约、冲突、只追加审计、逾期提醒和重试实现。自动化验证已覆盖核心红线。OIDC 生产提供方配置、HTTPS 反向代理、独立备份存储和用户人工验收仍属于发布前事项；不将这些事项伪造为已完成。ADR-0001 至 ADR-0008 均为已接受边界，Phase 2/3 仍仅为规划。
