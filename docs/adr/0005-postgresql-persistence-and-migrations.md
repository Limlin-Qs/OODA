# ADR-0005 PostgreSQL 持久化、并发与迁移

## 状态

Accepted（2026-09-14）。尚未实现。

## 背景

设备占用、引用完整性、审计同事务和并发冲突必须由权威持久化层保证，不能只依赖前端或应用层先查后写。

## 决策

- 使用 PostgreSQL 作为首版权威数据库。
- 所有 schema 变化使用版本化 SQL 迁移；迁移执行必须有锁或等价机制，禁止手工修改共享环境。
- 使用外键、唯一约束、事务和数据库级原子冲突控制保证设备、成员、借用、预约和审计的一致性。
- 占用冲突采用 PostgreSQL 可证明的排斥约束、锁或等价原子写入，并用真实数据库并发测试验证。
- 具体迁移 runner 属于可替换实施细节，在 G-009 锁定并写入运行说明。

## 替代方案

- SQLite：部署简单，但需要额外证明共享部署下的并发和恢复边界，首版不采用。
- ORM 自动 schema 同步：容易绕过显式迁移审查，首版不作为 schema 权威方式。
- 仅应用层冲突查询：存在竞争窗口，拒绝。

## 后果

可直接利用事务、外键、唯一性和并发控制；需要运行 PostgreSQL，并维护迁移、备份和恢复流程。

## 当前实现与差距

当前没有数据库、迁移、schema 或备份实现。

## 不在范围

不决定云数据库提供商、备份产品或个人数据匿名化细节。

## 复核条件

出现多地域写入、跨服务事务或实际容量证据时重新评估。
