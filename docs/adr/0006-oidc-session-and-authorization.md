# ADR-0006 OIDC 身份、会话与服务端授权

## 状态

Accepted（2026-09-14）。部分实现（2026-10-13 核对）：OIDC 验证边界、HttpOnly 会话和服务端授权已落地；生产 IdP 配置与成员管理入口仍待完成。

## 背景

系统必须识别真实操作者，并限制普通成员只能操作本人资源。浏览器自报用户 ID 或前端隐藏按钮都不能构成安全边界。

## 决策

- 使用组织现有 OIDC 身份源；系统保存身份 subject 到成员的服务端映射。
- 使用服务端 HttpOnly 会话，浏览器不持久化会话密钥或权威业务状态。
- 角色只有管理员和普通成员；角色授予、停用和成员有效性由服务端管理。
- 服务端默认拒绝未明确允许的操作，所有资源所有权和可见性在服务端检查。
- 停用成员不能创建新借用或预约，历史责任链继续可追溯。

## 替代方案

- 本地密码：会增加密码哈希、重置、防暴力破解和凭据生命周期责任，首版不采用。
- 仅使用前端角色标记：不能防止伪造请求，拒绝。
- 浏览器保存 JWT 作为唯一状态：扩大令牌泄露面，首版不采用。

## 后果

不重复建设密码系统，服务端可以统一执行授权；需要组织提供 OIDC 配置和成员映射管理。

## 当前实现与差距（2026-10-13 核对）

已实现事实：jose 实现 OIDC 授权码流程（含 state/nonce 登录状态表与一次性消费）；会话为不透明随机令牌，仅存 SHA-256 哈希，cookie 属性 `HttpOnly`、`SameSite=Lax`，生产加 `Secure`；首次登录按 `identity_subject` 自动建档成员（默认 `member`/`active`）；授权在服务端逐命令执行（`assertActiveMember`/`assertAdmin`），资源所有权逐条校验，停用成员拒绝新操作；注销即删除会话。集成测试覆盖伪造用户 ID 与越权拒绝。

现状差距（待确认/待部署）：应用内没有角色授予、成员停用或成员管理写接口，`admin`/`inactive` 目前只能直接改数据库（E2E 脚本即如此）；首个管理员引导方式未定义；OIDC 生产提供方（issuer、client、密钥）待部署配置；会话 TTL 固定 8 小时、无续期策略。

## 不在范围

不实现新的身份提供商、密码管理器、组织目录同步平台或复杂 RBAC。

## 复核条件

组织身份源不可用、需要离线使用或角色模型显著扩展时重新评估。
