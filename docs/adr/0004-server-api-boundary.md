# ADR-0004 服务端与 API 边界

## 状态

Accepted（2026-09-14）。尚未实现。

## 背景

React/Vite 只能提供浏览器客户端，不能承担身份、权限、事务、并发占用或审计职责。首版需要一个单一、可持久化的服务端边界。

## 决策

- 使用当前活跃 Node.js LTS 与 TypeScript 构建独立服务端。
- 使用 Fastify 提供 REST/JSON API；React 前端通过 API 读取和提交业务命令。
- 服务端负责身份映射、授权、服务端时间、业务校验、事务写入和错误语义。
- API 不信任客户端提交的操作者 ID；操作者来自服务端验证的会话。

## 替代方案

- 使用 Next.js 等全栈框架：会提前绑定前后端一体化部署，当前不采用。
- 使用 Go 服务端：可行，但当前已确认 TypeScript 服务端边界，首版不增加语言边界。
- 纯静态前端或浏览器存储：无法满足共享、权限和并发不变量，拒绝。

## 后果

前后端职责清楚，便于集成和并发测试；代价是必须维护独立服务端运行时和 API 契约。

## 当前实现与差距

当前只有 Vite React 模板；服务端、API、错误模型和健康检查尚未实现。

## 不在范围

不决定具体数据库、身份提供商、通知渠道或部署提供商。

## 复核条件

若产品改为 SSR、全栈一体化或需要不同语言的运行时约束，重新评估。
