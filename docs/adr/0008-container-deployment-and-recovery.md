# ADR-0008 容器化部署与恢复边界

## 状态

Accepted（2026-09-14）。Phase 1 实现已落地；生产环境配置待人工验收。

## 背景

静态前端构建产物不能构成完整产品；生产环境还需要服务端、数据库、HTTPS、迁移、备份、日志脱敏和回退流程。

## 决策

- 目标环境为 Linux 容器化部署，应用通过 HTTPS 反向代理对外提供服务。
- 配置通过受控环境注入；真实密钥不进入源码、镜像、前端构建或日志。
- 发布前按顺序执行兼容迁移、应用发布和健康检查；失败时回退到上一可运行构建，并按迁移兼容策略处理数据。
- PostgreSQL 备份保存到独立位置；发布前和定期执行恢复演练并记录结果。
- 日志默认脱敏，不记录会话密钥、连接串、密码或不必要的联系方式。
- 具体云/主机提供商属于部署实施细节，在发布验收前明确责任人和操作手册。

## 替代方案

- 仅部署静态前端：无法承载权威业务能力，拒绝。
- 工作室内网裸机部署：可行，但首版仍需补齐 HTTPS、备份和恢复责任，暂不作为默认方案。
- 无备份直接发布：无法满足恢复验收，拒绝。

## 后果

部署可重建、发布和恢复边界清楚；需要容器运行环境、HTTPS 证书管理、备份存储和演练责任。

## 当前实现与差距

仓库已有 `ops/Dockerfile`、`ops/.dockerignore`、`ops/backup.sh`、`ops/restore.sh`、`ops/recovery-rehearsal.sh` 和 `docs/operations/release-recovery.md`；服务端有 `/healthz`。本地验证已完成重复迁移、custom dump 校验和恢复到隔离数据库。具体 HTTPS 反向代理、独立备份存储、责任人和生产回退演练仍需部署环境人工完成。

## 不在范围

不承诺具体 SLA、容量、云厂商、跨地域灾备或自动扩缩容。

## 复核条件

部署环境、数据保留法规或可用性要求发生变化时重新评估。
